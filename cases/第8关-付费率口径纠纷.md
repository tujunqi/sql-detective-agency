## 二、【指标卷宗】付费率：分子定"谁付了钱"，分母定"在谁里面数"

**付费率** = 统计周期内**有效付费**的去重用户数 ÷ 同周期的**活跃用户数**（或指定人群）。

### 口径 A：月活跃付费率（行业标准）

- **计算逻辑**：分子 = 周期内 `paid` 且 `金额 > 0` 且未整单退款 的**去重用户**；分母 = 同周期活跃用户数。
- **适用场景**：产品变现效率的月度健康度，可画趋势线。
- **歧义坑点**：分子必须**去重**（一人买两门课只算一人）；0 元单、整单退款的处理要写死在口径里。

### 口径 B：新增用户付费率（新客转化）

- **计算逻辑**：分子分母都限定在当月新增用户——"新客当月付费率"。
- **适用场景**：衡量投放质量与首单转化链路，商业化投放组的生命线。
- **歧义坑点**：它是另一个指标！新客规模小、决策链长，数字天然低于全量付费率——**拿它当"付费率暴跌"的证据，属于偷换分母**。

### 口径 C：订单口径（错，但很常见）

- **计算逻辑**：订单笔数 ÷ 活跃用户数。
- **适用场景**：没有适用场景——它连"率"都不是，分子没去重，一个人买两门课就被数两次。
- **歧义坑点**：客单价越高的教育产品，一人多单越常见，这个"率"越失真；极端情况能算出超过 100%。

### 试购与退款的行业惯例

| 情形 | 主流处理 | 理由 |
|---|---|---|
| 0 元体验课/试购 | 不计入付费用户（可单列"0 元转化率"） | 没有支付行为，不构成付费意愿证据 |
| 整单退款 | 从付费用户中剔除（或当月回冲） | 钱没留下，付费行为不成立 |
| 部分退款 | 保留付费用户身份，金额按净额 | 有真实支付意愿 |
| 试购后二次正价购买 | 正常计入 | 有效付费 |

### 面试标准回答话术

> "付费率我会先钉四件事：**分母人群**（全量活跃还是新增用户）、**分子去重**（用户数不是订单数）、**0 元单处理**（默认不计入，单列试购转化）、**退款处理**（整单退款剔除）。标准句式是'9 月活跃用户付费率 X%，其中新客付费率 Y%'——两个数并列汇报，谁也不抢谁的名字。"

### 新手最容易踩的错误统计方式

1. **分子用订单数**：不去重用户，付费率随客单结构波动。
2. **0 元单混进分子**：体验课拉新越猛，付费率越虚高。
3. **退款不回冲**：退款率高的月份，付费率虚高。
4. **分母口径漂移**：这个月用全量活跃、下个月用新增用户，趋势线直接断裂。

## 四、【探案任务】

> ⏱️ **限时挑战**：第 2 步建议计时 **5 分钟**完成"限时解码"。

### 第 1 步 · 口径对齐

给"9 月付费率"定版，下面哪个口径能同时服住增长组和商业化组？

- A. 有订单记录（含 0 元单与退款）的去重用户 ÷ 全部活跃用户
- B. 有效付费用户（paid 且金额 > 0，整单退款剔除）÷ 全部活跃用户，另附"新客付费率"
- C. 付费订单笔数 ÷ 全部活跃用户

<details>
<summary>点击核对答案</summary>

**选 B，并且必须"另附新客"**。A 把 0 元体验单（u27）和整单退款（u26）都算成"付费"，商业化组的质疑成立；C 的分子是订单数，u22 一人两门课被数两次。B 的正确付费率是 8.0%；商业化组心心念念的"新客付费率 5.0%"作为并列指标保留——它低是事实，但那是新客转化的问题，不是"付费率暴跌"。

</details>

### 第 2 步 · 基础核算（限时 5 分钟）

按口径 B 写出 9 月付费率：分子筛"paid 且 pay_amount > 0"的去重用户，分母用 9 月活跃用户数。

<details>
<summary>卡住了？点击看提示</summary>

两个子查询相除：分子 `COUNT(DISTINCT user_id) FROM order_info WHERE order_status='paid' AND pay_amount > 0`；分母 `COUNT(DISTINCT user_id) FROM user_active_log`。0 元单被 `pay_amount > 0` 自然挡掉——这就是"试购不计入"的 SQL 实现。

</details>

### 第 3 步 · 真相追踪

12% 和 5% 各是谁？写 SQL：① 复现报表 A（含 0 元单与退款用户）；② 复现报表 B（新客口径）；③ 把 0 元单和退款单列成清单，④ 按"9 月新增 / 老用户"分组对比付费率。

<details>
<summary>点击看提示</summary>

② 分母 JOIN 注册表限定新增人群；④ 用 `LEFT JOIN user_register` 给活跃用户打"新增/老用户"标签，`CASE WHEN` 分组算各自的付费率——你会发现新客 5%、老客 10%，"转化问题"和"付费率问题"从此各归各。

</details>

## 五、【真相大白】

### 5.1 异常根因拆解

**正确的 9 月活跃用户付费率 = 8.0%**（4/50）。两个报表的数字各有来路：

1. **增长组的 12.0% = 分子掺了水**。6 个"有订单记录的用户"里，u27 只有 0 元体验课订单（没有支付行为），u26 的订单已整单退款（钱没留下）。真正的有效付费用户只有 4 人（u21、u22、u23、u07）——0 元单 + 退款单让分子虚增 2 人，付费率从 8.0% 被抬到 12.0%。
2. **商业化组的 5.0% = 分母偷了人**。它算的是"**9 月新增用户付费率**"：20 个新客里 1 人付费（u07，9 月 12 日买课的新用户）。这个口径本身合法且重要，但它不是"9 月付费率"——新客还在决策期，转化天然低。拿它冒充付费率，等于宣告"投放要停"的死刑误判。
3. **一个被忽略的真信号**：新客付费率 5.0% vs 老客付费率 10.0%——新客转化确实只有老客的一半，这才是商业化组真正该跟进的业务问题（新手引导、首单优惠、体验课转正价），而不是口径吵架。
4. **订单口径的陷阱**：7 笔订单 ÷ 50 人 = 14.0%，比正确值虚高 6 个百分点——u22 一人买两门课被数两次，教育行业高客单、多课程的结构让这个错法格外失真。

### 5.2 参考答案 SQL（逐行注释）

```sql
USE case08_pay_rate;

-- 【第2步 · 正确答案：9 月活跃用户付费率】
SELECT
  (SELECT COUNT(DISTINCT user_id) FROM order_info
    WHERE order_status = 'paid'                -- 支付成功
      AND pay_amount > 0)                      -- 且金额 > 0：0 元体验单不算付费
    AS paying_users,                           -- 4 人（u21、u22、u23、u07）
  (SELECT COUNT(DISTINCT user_id) FROM user_active_log)
    AS active_users,                           -- 50 人（9 月活跃）
  ROUND((SELECT COUNT(DISTINCT user_id) FROM order_info
          WHERE order_status = 'paid' AND pay_amount > 0) /
        (SELECT COUNT(DISTINCT user_id) FROM user_active_log) * 100, 1)
    AS pay_rate_correct                        -- 8.0%
FROM DUAL;
-- 注：整单退款单 status='refunded'，被 order_status='paid' 自然排除——"退款不计入"的 SQL 实现

-- 【第3步-① · 复现报表 A：0 元单 + 退款用户全算"付费"】
SELECT
  (SELECT COUNT(DISTINCT user_id) FROM order_info)   AS users_incl_free,      -- 6 人
  ROUND((SELECT COUNT(DISTINCT user_id) FROM order_info) /
        (SELECT COUNT(DISTINCT user_id) FROM user_active_log) * 100, 1)
    AS pay_rate_report_a;                            -- 12.0%

-- 【第3步-② · 复现报表 B：新客付费率（分母偷换）】
SELECT
  (SELECT COUNT(DISTINCT o.user_id) FROM order_info o
    JOIN user_register r ON r.user_id = o.user_id    -- 人群限定：9 月新增
    WHERE o.order_status = 'paid' AND o.pay_amount > 0) AS new_payers,       -- 1 人（u07）
  (SELECT COUNT(*) FROM user_register)               AS new_users,            -- 20 人
  ROUND((SELECT COUNT(DISTINCT o.user_id) FROM order_info o
          JOIN user_register r ON r.user_id = o.user_id
          WHERE o.order_status = 'paid' AND o.pay_amount > 0) /
        (SELECT COUNT(*) FROM user_register) * 100, 1)
    AS pay_rate_report_b;                            -- 5.0%

-- 【第3步-③ · 0 元单与退款单清单】
SELECT
  order_id, user_id, order_status, pay_amount,
  CASE WHEN pay_amount = 0 THEN '0元体验单'
       WHEN order_status = 'refunded' THEN '整单退款'
       ELSE '正常单' END AS order_kind
FROM order_info
WHERE pay_amount = 0 OR order_status = 'refunded';
-- 结果：d07/u27/paid/0（0元体验单）；d06/u26/refunded/399（整单退款）

-- 【第3步-④ · 新客 vs 老客付费率：各归各的业务问题】
SELECT
  CASE WHEN r.user_id IS NOT NULL THEN '9月新增' ELSE '老用户' END AS cohort,
  COUNT(DISTINCT a.user_id) AS users,
  COUNT(DISTINCT CASE WHEN o.order_status = 'paid' AND o.pay_amount > 0
                      THEN a.user_id END) AS payers,
  ROUND(COUNT(DISTINCT CASE WHEN o.order_status = 'paid' AND o.pay_amount > 0
                            THEN a.user_id END)
        / COUNT(DISTINCT a.user_id) * 100, 1) AS pay_rate
FROM user_active_log a
LEFT JOIN user_register r ON r.user_id = a.user_id
LEFT JOIN order_info o    ON o.user_id = a.user_id
GROUP BY cohort;
-- 结果：9月新增 20 人/1 付费/5.0%；老用户 30 人/3 付费/10.0%

-- 【错误写法 · 订单口径：订单笔数 ÷ 活跃用户】
SELECT ROUND((SELECT COUNT(*) FROM order_info) /
       (SELECT COUNT(DISTINCT user_id) FROM user_active_log) * 100, 1) AS pay_rate_wrong; -- 14.0%
```

### 5.3 错误写法对比

**错误写法一：分子不剔 0 元单和退款（报表 A 的口径）**

```sql
SELECT ROUND((SELECT COUNT(DISTINCT user_id) FROM order_info) /
       (SELECT COUNT(DISTINCT user_id) FROM user_active_log) * 100, 1) AS pay_rate;  -- 错
```

错在哪：算出 **12.0%**，比正确值 8.0% **虚高 4 个百分点（+50%）**。0 元体验单没有支付行为、整单退款钱没留下，都不构成"付费用户"。教育行业体验课拉新占比越高，这个虚高越大——增长组用它汇报，等于把拉新成果伪装成变现成果。

**错误写法二：订单笔数当分子**

```sql
SELECT ROUND((SELECT COUNT(*) FROM order_info) /
       (SELECT COUNT(DISTINCT user_id) FROM user_active_log) * 100, 1) AS pay_rate;  -- 错
```

错在哪：算出 **14.0%**，虚高 6 个百分点。u22 一人两门课被数两次——分子没去重，"率"的分母是人、分子却是单，量纲都不一致。付费率超过常识（教育行业月付费率通常个位数到 15%）时，先检查是不是订单口径。

## 六、【侦探办案笔记】

### 本关指标口径总结

- 付费率四要素：**分母人群、分子去重、0 元单处理、退款处理**。
- 标准句式双线汇报："9 月活跃用户付费率 8.0%，其中新客付费率 5.0%"——两个指标并列，谁也不冒充谁。
- 0 元试购单不计入付费，可单列"0 元转化率"；整单退款剔除或当月回冲。
- 量纲自检：分子分母必须同为"人数"；分子是订单数的"率"一律打回重写。

### 业务方对齐口径的标准提问话术

1. "这个付费率的**分母是全量活跃还是新增用户**？两个数我要并列看。"
2. "**0 元体验课和退款**算不算付费？行业惯例是怎么处理的？"
3. "分子是**用户数还是订单数**？一人多单怎么算？"

### 同类异常排查的通用方法论

"付费指标两个数"类案件三步走：

1. **把分子里的用户列成名单**：每个"付费用户"逐个过堂（真付费？0 元？退款？），掺水处自然现形；
2. **检查分母人群**：全量活跃、新增用户、注册存量——分母换一批人，数字换一个世界；
3. **拆队列找真信号**：新客 vs 老客、渠道维度、课程维度——口径吵架的背后，常常藏着一个没人看的真问题。
