## 一、【案情通报】

翻页资讯是信息流产品，广告按 CTR 计费权重分配流量。9 月 27 日还是健康的 **5.0%**（6 次点击 ÷ 120 次曝光），9 月 28 日突然飙到 **18.2%**（12 次点击 ÷ 66 次曝光）。

Amy 提供的三条现场线索：

1. 广告主反馈：点击量涨了，但**落地页转化一点没涨**；
2. 运维值班记录：9-28 凌晨 3 点有一批来源不明的接口请求；
3. 客户端组当天发过一个新版，曝光埋点模块动过。

**任务目标**：还原 9-28 的真实 CTR，判定 18.2% 里的水分来自哪几处、真实提升有多少，给广告主一份能保住投放的结案报告。

## 二、【指标卷宗】CTR：分子分母都会撒谎的指标

**CTR（Click-Through Rate）** = 点击次数 ÷ 曝光次数。难点不在公式，在"什么算一次点击、什么算一次曝光"。

### 口径 A：曝光口径（分母的地基）

- **计算逻辑**：卡片**进入屏幕有效区域**（常见标准：露出 ≥50% 且停留 ≥1 秒）才记一次曝光。
- **适用场景**：行业默认口径，广告计费与 CTR 统计的底座。
- **歧义坑点**：口径一旦漂移（"进入屏幕即算"混进"停留 1 秒"的口径），曝光虚大、CTR 骤降；反过来**曝光埋点丢失**（发版事故），分母骤减、CTR 飙升——本案的分母病灶。

### 口径 B：点击口径（分子的免疫机制）

- **计算逻辑**：去重后的有效点击 ÷ 有效曝光。同一设备对同一卡片的**短时连点**应去重（防抖），**机器流量**（爬虫、脚本）应整体剔除。
- **适用场景**：广告效果评估的分子标准。
- **歧义坑点**：客户端未做防抖时，用户手抖连点 3 次被记 3 次；爬虫直接请求点击接口，**不产生曝光却有点击**——分子虚增同时分母不涨，CTR 双重放大。

### 口径 C：位置/内容分层 CTR

- **计算逻辑**：按信息流位置（首位、次位…）或内容类型拆分统计 CTR。
- **适用场景**：推荐策略评估——首位卡片 CTR 天然是末位的几倍，位置结构变化会带来"结构性 CTR 上升"。
- **歧义坑点**：整体 CTR 上涨不一定是内容变好，可能只是**爆款被排到了前面**（位置偏差）——这部分是真实的策略收益，但它和"数据污染"涨在一起时必须拆开算账。

### 行业差异速记

| 行业 | CTR 基准 | 特殊之处 |
|---|---|---|
| 信息流广告 | 1% ~ 5%（信息流位） | 首位可达末位 3~5 倍；反作弊是生命线 |
| 电商推荐位 | 3% ~ 8% | "加购率/转化率"比 CTR 更接近业务 |
| 邮件/推送 | 点击率 2% ~ 10%，但按送达量算分母 | 曝光=送达，口径不同不可与信息流混比 |

### 面试标准回答话术

> "CTR 异常我会分子分母两头查：**分子**做三道清洗——剔机器流量（无曝光的点击、等间隔节拍）、同设备同内容短时去重（防抖）、剔已识别的作弊设备；**分母**做一次校准——按人均曝光基线（健康日的人均曝光次数 × 当日设备数）检验曝光埋点是否漏报；清洗完剩下的涨幅，再按**位置结构**拆分，判断是真实的内容/策略收益还是位置偏差。"

### 新手最容易踩的错误统计方式

1. **原始数直接比**：不清洗分子不校准分母，18% 的"涨幅"里全是水分。
2. **只剔爬虫就收工**：清洗不彻底（重复点击还在、曝光漏报没补），数字"看起来合理"了，其实只是错得巧。
3. **涨幅全归因业务**：把污染涨幅当成策略收益去庆功，下个月数据一恢复，庆功宴就成了事故复盘会。

## 四、【探案任务】

> ⏱️ **限时挑战**：第 2 步建议计时 **5 分钟**完成"限时解码"。

### 第 1 步 · 口径对齐

给广告主的"真实 CTR"，应该怎么算？

- A. 原始点击 ÷ 原始曝光（报表现状，18.2%）
- B. 只剔爬虫点击，曝光照用
- C. 有效点击（剔机器流量 + 同设备同内容去重）÷ 校准后的曝光（按人均基线还原漏报）

<details>
<summary>点击核对答案</summary>

**选 C**。A 是被污染的原始数；B 只洗了分子——重复点击还在，曝光漏报还在（9-28 人均曝光 4.1 次 vs 前一天的 8.0 次，分母少了一半）。**分子分母必须同步清洗**，这是第 4 关学过的原则，在 CTR 上同样成立。

</details>

### 第 2 步 · 基础核算（限时 5 分钟）

写出有效点击的统计 SQL：9-28 点击中，剔除 `bot` 设备、同设备同卡片去重后剩几次？

<details>
<summary>卡住了？点击看提示</summary>

`SELECT COUNT(*) FROM (SELECT DISTINCT device_id, news_id FROM feed_click_log WHERE DATE(click_time)='2026-09-28' AND device_id NOT LIKE 'bot%') t`——先去重再计数，12 行变 8 行。

</details>

### 第 3 步 · 真相追踪

三步定位水分：① 找爬虫指纹——哪个设备的点击**没有任何曝光记录**、节拍是**等间隔**的？② 找重复点击——同设备同卡片几秒内连点？③ 校准分母——两天的"人均曝光次数"各是多少，差多少？

<details>
<summary>点击看提示</summary>

① bot 的点击 LEFT JOIN 曝光表，曝光数 = 0 实锤；② 自连接 `c2.click_time BETWEEN c1.click_time AND c1.click_time + INTERVAL 5 SECOND`；③ 人均曝光 = 曝光行数 ÷ 去重设备数，两天一比，4.1 vs 8.0 说明分母少了一半。

</details>

## 五、【真相大白】

### 5.1 异常根因拆解

**修正后的 9-28 真实 CTR = 6.3%**，相比基线 5.0% 有 **+1.3 个百分点的真实提升**——推荐策略当天把高点击率的卡片排到了前位，这部分是实打实的策略收益。18.2% 里的水分由三股构成：

1. **爬虫流量（分子虚增）**：bot_001 在凌晨 3 点以 **5 秒等间隔**连击 3 次点击接口——**该设备在 9-28 没有任何曝光记录**（脚本直连接口，不经前端页面），点击有了、曝光没有，CTR 的分子白白 +3。
2. **重复点击（分子虚增）**：d02 对卡片 n07 在 **1 秒内连点 2 次**（客户端未做防抖），原始数据算 2 次点击，有效点击只有 1 次。
3. **曝光漏报（分母骤减）**：9-28 发版后曝光埋点漏报——人均曝光从前一天的 **8.0 次**跌到 **4.1 次**，16 台设备本应产生约 128 次曝光，实际只上报 66 次。分母腰斩，CTR 直接翻倍。
4. **验算**：有效点击 8 ÷ 校准曝光 128（16 台 × 人均 8.0）= **6.25% ≈ 6.3%**。给广告主的说法：18.2% 中约 12 个百分点是数据污染，+1.3pp 是真实策略收益——**转化没涨是正常的，点击质量没变，涨的是数字不是效果。**

### 5.2 参考答案 SQL（逐行注释）

```sql
USE case09_ctr;

-- 【基线 · 9-27 CTR】
SELECT
  (SELECT COUNT(*) FROM feed_click_log WHERE DATE(click_time) = '2026-09-27')       AS clicks,     -- 6
  (SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-27') AS exposures,  -- 120
  ROUND((SELECT COUNT(*) FROM feed_click_log WHERE DATE(click_time) = '2026-09-27') /
        (SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-27') * 100, 1)
    AS ctr_baseline                                                                -- 5.0%
FROM DUAL;

-- 【报表现状 · 原始 9-28 CTR（被污染）】
SELECT
  (SELECT COUNT(*) FROM feed_click_log WHERE DATE(click_time) = '2026-09-28')       AS clicks_raw,    -- 12
  (SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-28') AS exposures_raw, -- 66
  ROUND((SELECT COUNT(*) FROM feed_click_log WHERE DATE(click_time) = '2026-09-28') /
        (SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-28') * 100, 1)
    AS ctr_raw                                                                     -- 18.2%
FROM DUAL;

-- 【第2步 · 分子清洗：剔爬虫 + 同设备同内容去重】
SELECT COUNT(*) AS valid_clicks                 -- 有效点击 = 8
FROM (SELECT DISTINCT device_id, news_id        -- 同设备同卡片去重（防抖）
      FROM feed_click_log
      WHERE DATE(click_time) = '2026-09-28'
        AND device_id NOT LIKE 'bot%') t;       -- 剔机器流量

-- 【第3步-① · 爬虫指纹：有点击、无曝光 + 等间隔节拍】
SELECT
  c.device_id, c.news_id, c.click_time,
  (SELECT COUNT(*) FROM feed_exposure_log e
    WHERE e.device_id = c.device_id
      AND DATE(e.exposure_time) = '2026-09-28') AS exposures_of_device  -- bot 全为 0
FROM feed_click_log c
WHERE c.device_id = 'bot_001';
-- 结果：3 次点击、0 次曝光、5 秒等间隔——机器流量的标准指纹

-- 【第3步-② · 重复点击：同设备同卡片 5 秒内连点】
SELECT
  c1.device_id, c1.news_id,
  c1.click_time AS first_click,
  c2.click_time AS second_click
FROM feed_click_log c1
JOIN feed_click_log c2
  ON  c1.device_id = c2.device_id
  AND c1.news_id   = c2.news_id
  AND c2.click_time >  c1.click_time
  AND c2.click_time <  c1.click_time + INTERVAL 5 SECOND
WHERE DATE(c1.click_time) = '2026-09-28';
-- 结果：d02 对 n07，10:00:00 与 10:00:01——客户端未防抖

-- 【第3步-③ · 分母校准：人均曝光对比】
SELECT
  ROUND((SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-27') /
        (SELECT COUNT(DISTINCT device_id) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-27'), 1)
    AS avg_exp_27,   -- 8.0（健康基线）
  ROUND((SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-28') /
        (SELECT COUNT(DISTINCT device_id) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-28'), 1)
    AS avg_exp_28   -- 4.1（漏报一半，实锤）
FROM DUAL;

-- 【最终答案 · 修正 CTR】有效点击 ÷ (当日设备数 × 前日人均曝光)
SELECT
  (SELECT COUNT(DISTINCT device_id) FROM feed_exposure_log
    WHERE DATE(exposure_time) = '2026-09-28')                        AS devices_28,   -- 16 台
  ROUND((SELECT COUNT(*) / COUNT(DISTINCT device_id) FROM feed_exposure_log
          WHERE DATE(exposure_time) = '2026-09-27'), 1)               AS avg_exp_27,   -- 8.0
  ROUND((SELECT COUNT(*) FROM (SELECT DISTINCT device_id, news_id FROM feed_click_log
          WHERE DATE(click_time) = '2026-09-28' AND device_id NOT LIKE 'bot%') t) /
        ((SELECT COUNT(DISTINCT device_id) FROM feed_exposure_log
           WHERE DATE(exposure_time) = '2026-09-28') *
         (SELECT COUNT(*) / COUNT(DISTINCT device_id) FROM feed_exposure_log
           WHERE DATE(exposure_time) = '2026-09-27')) * 100, 1)       AS ctr_corrected  -- 6.3%
FROM DUAL;

-- 【位置结构 · 涨幅里的真实收益】
SELECT slot_position, COUNT(*) AS exposures
FROM feed_exposure_log
WHERE DATE(exposure_time) = '2026-09-28'
GROUP BY slot_position
ORDER BY slot_position;

-- 【错误写法对照 · 只剔爬虫不修分母】
SELECT ROUND((SELECT COUNT(*) FROM feed_click_log
              WHERE DATE(click_time) = '2026-09-28' AND device_id NOT LIKE 'bot%') /
             (SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-28') * 100, 1)
    AS ctr_wrong2   -- 13.6%
FROM DUAL;
```

### 5.3 错误写法对比

**错误写法一：原始数直接上报（现状报表）**

```sql
SELECT ROUND(12 / 66 * 100, 1) AS ctr_raw;   -- 18.2%
```

错在哪：18.2% 是三股污染的叠加态——分子混着爬虫与连点，分母漏了一半曝光。拿着它去和广告主谈判，等于主动承认刷量。

**错误写法二：只剔爬虫就收工**

```sql
SELECT ROUND((SELECT COUNT(*) FROM feed_click_log
              WHERE DATE(click_time) = '2026-09-28' AND device_id NOT LIKE 'bot%') /
             (SELECT COUNT(*) FROM feed_exposure_log WHERE DATE(exposure_time) = '2026-09-28') * 100, 1) AS ctr;
```

错在哪：算出 **13.6%**——比 18.2% "合理多了"，但离真实的 6.3% 还差 7.3 个百分点。重复点击没去重、曝光漏报没校准，**清洗不彻底等于没洗**：数字从"明显造假"变成了"悄悄失真"，后者更危险。

## 六、【侦探办案笔记】

### 本关指标口径总结

- CTR 清洗双轨制：**分子**剔机器流量（无曝光的点击、等间隔节拍）+ 同设备同内容去重；**分母**用人均曝光基线校准漏报。
- 爬虫指纹三件套：**有下游无上游**（点击无曝光）、**等间隔节拍**、**异常时段**（凌晨三点）。
- 修正后的涨幅要按位置结构拆分——首位承载更多曝光带来的"结构性上升"是真实策略收益，但要单独说明。
- 曝光口径（露出 ≥50% 停留 ≥1s）一旦变更，历史 CTR 全部不可比，必须发口径公告。

### 业务方对齐口径的标准提问话术

1. "曝光的**有效标准**是什么？最近有没有改过曝光埋点？"
2. "点击**做了防抖去重吗**？机器流量的剔除名单多久更新？"
3. "CTR 涨的时候，**转化涨了吗**？没涨的话先查数据再谈业务。"

### 同类异常排查的通用方法论

"比率指标异常"类案件（分子分母双污染）四步走：

1. **分子体检**：`DISTINCT` 去重、剔已知机器流量、按设备频率找异常；
2. **分母体检**：拿健康基线（人均曝光、人均会话）对比事发日，漏报/口径漂移当场现形；
3. **残差归因**：清洗后的涨幅按位置/内容/渠道拆分，区分"真实收益"与"结构偏差"；
4. **对外统一口径**：给广告主/老板的数字必须注明清洗规则，否则下个月还得重新吵一遍。
