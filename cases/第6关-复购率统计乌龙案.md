## 一、【案情通报】

鲜果盒子是一家生鲜电商，用户买水果蔬菜，频次天然高。9 月经营会上，会员运营小林汇报：**9 月复购率 65%**。老板当场质疑：生鲜行业月复购率普遍 30%~40%，65% 意味着三分之二的顾客一个月内买了又买，不合常理。

小林的算法是：

> "9 月下单的 20 个用户里，有 13 个下了 2 单以上——13 ÷ 20 = 65%。SQL 没有任何报错。"

老板的直觉是：

> "生鲜是高频，但也不至于高频成这样。再说了，一个月里买两次就叫'复购'？那我早上买俩苹果晚上买仨橙子，也算复购？"

**任务目标**：用正确的复购口径重算 9 月数据，说清楚小林的 65% 到底是什么、正确的数字是多少，并给出复购率的标准定义。

## 二、【指标卷宗】复购率：先问"谁、从哪天开始、多长时间内"

**复购率** = 在统计周期内**再次购买**的用户占某个**购买用户队列**的比例。这句话里有三个必须钉死的词：**队列**（谁）、**锚点**（从哪天起算）、**窗口**（多长时间内）。

### 口径 A：周期复购率（队列 + 窗口，行业标准）

- **计算逻辑**：某月**首购**用户中，在首购后 N 天内（常见 60/90 天）再次购买的比例。例："7 月首购用户的 90 天复购率"。
- **适用场景**：衡量新客留存与产品复购力， cohort 分析的标准动作。
- **歧义坑点**：必须以**首购**为锚点——首购之后的第二单才算复购，第三、四单不能当新的锚点重复计数。

### 口径 B：月内多单率（错，但最常被当成复购率）

- **计算逻辑**：当月下单 ≥2 次的用户 ÷ 当月所有下单用户。
- **适用场景**：它不是复购率，它是"月内多单率"——衡量的是单用户月内购买频次结构。
- **歧义坑点**：**没有跨周期锚点**。生鲜、日百这类高频品类，月内多单是常态，这个数天然虚高；小林的 65% 就是它。

### 口径 C：任意两单口径（宽）

- **计算逻辑**：历史上有过 ≥2 笔订单的用户 ÷ 所有购买用户。
- **适用场景**：粗略衡量"回头客比例"，对账、快查用。
- **歧义坑点**：不锚首购、不限定窗口——8 月首购 8 月复买、9 月首购 9 月复买全都混进来，比口径 A 系统性偏高。

### 行业差异速记

| 行业 | 复购窗口习惯 | 特殊之处 |
|---|---|---|
| 生鲜/日百 | 30 天/90 天复购率 | 高频低客单，月内多单率高≠复购率高 |
| 电商（综合） | 90 天/180 天复购率 | 按品类分层算（家电和零食不是一个周期） |
| 在线教育 | 续报率（课程周期决定） | "复购"体现为续报/扩科，窗口跟课时常走 |

### 面试标准回答话术

> "复购率必须先钉三个词：**队列**（哪个时间段的购买用户）、**锚点**（以首购为准，第二单才算复购）、**窗口**（首购后 N 天内）。标准句式是'X 月首购用户的 N 天复购率'。没有队列和窗口的'复购率'，和'月内多单率'不是一个指标。"

### 新手最容易踩的错误统计方式

1. **拿月内多单率当复购率**：没有跨周期锚点，高频品类直接虚高到失真。
2. **每一单都当锚点**：用户的第 2、3、4 单各自"开启"一次复购观察，同一用户被重复统计。
3. **不排除当期首购用户**：统计"9 月复购率"时把 9 月才首购、9 月又买的用户也算成"复购"，锚点都没出当月。

## 四、【探案任务】

> ⏱️ **限时挑战**：第 2 步建议计时 **5 分钟**完成"限时解码"。

### 第 1 步 · 口径对齐

要回答"我们产品的复购力到底怎么样"，应该采用哪种口径？

- A. 9 月下单 ≥2 单用户 ÷ 9 月下单用户（小林的算法）
- B. 7 月首购用户中，首购后 90 天内再次购买的比例
- C. 历史上有过 ≥2 笔订单的用户 ÷ 所有购买用户

<details>
<summary>点击核对答案</summary>

**选 B**。它有队列（7 月首购用户）、有锚点（首购时间）、有窗口（90 天），是可以跨月对比、可以和行业基准对话的标准口径。A 是"月内多单率"——高频生鲜品类天然偏高；C 是"任意两单比例"，不锚首购、不限窗口，只能当粗查参考。汇报句式：**"7 月首购用户的 90 天复购率是 35%。"**

</details>

### 第 2 步 · 基础核算（限时 5 分钟）

计算"7 月首购用户的 90 天复购率"：先用 `MIN(order_time)` 找出每个用户的首购时间并筛出 7 月首购队列，再判断队列中每个人在首购后 90 天内是否有第二笔订单。

<details>
<summary>卡住了？点击看提示</summary>

CTE `first_order`：`GROUP BY user_id` 后 `MIN(order_time)`，用 `HAVING` 把首购时间限定在 7 月。主查询用 `EXISTS`（相关子查询）判断"首购时间之后、首购时间 + 90 天之前"是否有另一笔订单。注意复购订单必须**晚于**首购时间。

</details>

### 第 3 步 · 真相追踪

65% 是怎么来的、35% 又是谁？写 SQL：① 复现小林的"月内多单率"；② 按"首购月份"给 9 月下单用户分组，看清 65% 里混了哪些人；③ 按用户对照"总单数 vs 是否 90 天内复购"。

<details>
<summary>点击看提示</summary>

② 把"9 月下单用户"和"每人首购月份"JOIN 起来按队列分组，你会发现 9 月下单的 20 人里有 8 个是 9 月才首购的新客——他们的"多单"根本和复购无关。

</details>

## 五、【真相大白】

### 5.1 异常根因拆解

**"7 月首购用户的 90 天复购率 = 35.0%"**（20 人中 7 人复购），与生鲜行业 30%~40% 的常识带完全吻合。小林的 65% 不是造假，是**指标装错了名字**：

1. **小林算的是"月内多单率"**：9 月下单的 20 人中 13 人当月下了 ≥2 单（13/20 = 65%）。这 13 个"多单用户"里，**7 个是 7 月首购的老客**（当月又买两次）、4 个是 8 月首购的次新、2 个是 9 月当月首购当月再买的新客——后两类人连"复购"的资格都还没有（首购锚点都没出当月），更不构成 90 天复购。
2. **老板的质疑精准命中**："早上买俩苹果晚上买仨橙子也算复购？"——月内多单率没有跨周期锚点，同一批买菜需求拆成两单也算"多单"。生鲜高频，这个指标天然在 60% 以上，拿它对标行业复购率是自找的冤案。
3. **任意两单口径是第三个陷阱**：40 个历史购买用户中 16 个有 ≥2 单（40%），看着接近 35%，但它把 8 月首购当月复买、9 月首购当月复买全算进去了——没锚首购、不限窗口，比标准口径系统性偏高 5 个百分点，且无法跨月对比。

### 5.2 参考答案 SQL（逐行注释）

```sql
USE case06_repurchase;

-- 【第2步 · 正确答案：7 月首购用户的 90 天复购率】
WITH first_order AS (
  SELECT
    user_id,
    MIN(order_time) AS first_time          -- 首购时间：每用户最早的支付订单
  FROM order_info
  WHERE order_status = 'paid'              -- 退款单不算购买（本现场全为 paid）
  GROUP BY user_id
  HAVING MIN(order_time) >= '2026-07-01'   -- 队列：7 月首购
     AND MIN(order_time) <  '2026-08-01'
)
SELECT
  COUNT(*) AS cohort_users,                -- 队列人数 = 20
  SUM(EXISTS(                              -- 每人：首购后 90 天内是否还有第二单
    SELECT 1 FROM order_info o2
    WHERE o2.user_id   = f.user_id
      AND o2.order_status = 'paid'
      AND o2.order_time >  f.first_time            -- 复购必须晚于首购
      AND o2.order_time <  f.first_time + INTERVAL 90 DAY  -- 窗口：90 天
  )) AS repurchase_users,                  -- 复购人数 = 7
  ROUND(SUM(EXISTS(
    SELECT 1 FROM order_info o2
    WHERE o2.user_id   = f.user_id
      AND o2.order_status = 'paid'
      AND o2.order_time >  f.first_time
      AND o2.order_time <  f.first_time + INTERVAL 90 DAY))
    / COUNT(*) * 100, 1)                   AS repurchase_rate  -- 35.0
FROM first_order f;

-- 【第3步-① · 复现小林的"月内多单率"】
WITH sep_orders AS (
  SELECT user_id, COUNT(*) AS n
  FROM order_info
  WHERE order_time >= '2026-09-01' AND order_time < '2026-10-01'
  GROUP BY user_id
)
SELECT
  COUNT(*)                      AS sep_buyers,        -- 9 月下单 20 人
  SUM(n >= 2)                   AS multi_buyers,      -- 当月 ≥2 单 13 人
  ROUND(SUM(n >= 2) / COUNT(*) * 100, 1) AS bad_rate  -- 65.0（这是多单率，不是复购率）
FROM sep_orders;

-- 【第3步-② · 9 月下单用户的队列结构：65% 里混了谁】
WITH sep_orders AS (
  SELECT user_id, COUNT(*) AS n
  FROM order_info
  WHERE order_time >= '2026-09-01' AND order_time < '2026-10-01'
  GROUP BY user_id
),
first_order AS (
  SELECT user_id, MIN(order_time) AS first_time
  FROM order_info WHERE order_status = 'paid'
  GROUP BY user_id
)
SELECT
  CASE WHEN MONTH(f.first_time) = 7 THEN '7月首购老客'
       WHEN MONTH(f.first_time) = 8 THEN '8月首购次新'
       ELSE '9月首购新客' END          AS cohort,
  COUNT(*)     AS buyers,       -- 该队列 9 月还在买的人数
  SUM(s.n)     AS orders,       -- 贡献订单数
  SUM(s.n >= 2) AS multi_buyers -- 当月多单人数
FROM sep_orders s
JOIN first_order f ON f.user_id = s.user_id
GROUP BY cohort
ORDER BY cohort;
-- 结果：7月首购老客 7 人/14 单/7 人多单；8月首购次新 5 人/9 单/4 人多单；9月新客 8 人/10 单/2 人多单
-- 9 月新客的"多单"与复购无关——首购锚点都没出当月

-- 【第3步-③ · 错法对照：任意两单口径】
WITH per_user AS (
  SELECT user_id, COUNT(*) AS cnt
  FROM order_info WHERE order_status = 'paid'
  GROUP BY user_id
)
SELECT
  COUNT(*)                    AS all_buyers,       -- 40
  SUM(cnt >= 2)               AS users_with_2plus, -- 16
  ROUND(SUM(cnt >= 2) / COUNT(*) * 100, 1) AS loose_rate -- 40.0
FROM per_user;
```

### 5.3 错误写法对比

**错误写法一：月内多单率当复购率（小林的 SQL）**

```sql
SELECT ROUND(SUM(n >= 2) / COUNT(*) * 100, 1) AS repurchase_rate  -- 错：这是月内多单率
FROM (SELECT user_id, COUNT(*) AS n FROM order_info
      WHERE order_time >= '2026-09-01' AND order_time < '2026-10-01'
      GROUP BY user_id) t;
```

错在哪：算出 **65.0%**，比正确的 90 天复购率 35.0% **虚高 30 个百分点**。它统计的是"当月买了几次"，不是"隔了多久又来买"——没有队列、没有锚点、没有窗口，高频品类必炸。指标名一改（"月内多单率"），它就是合法且有用的指标。

**错误写法二：任意两单口径（不锚首购、不限窗口）**

```sql
SELECT ROUND(SUM(cnt >= 2) / COUNT(*) * 100, 1) AS repurchase_rate  -- 错：这是"回头客比例"
FROM (SELECT user_id, COUNT(*) AS cnt FROM order_info
      WHERE order_status = 'paid' GROUP BY user_id) t;
```

错在哪：算出 **40.0%**，比正确口径**虚高 5 个百分点**。8 月首购当月复买、9 月首购当月再买的人全被计入"复购"，且每个用户的观察窗都不同，数字既不能和行业基准比，也不能跨月追踪。面试里说出"以首购为锚点"这五个字，这道题就稳了。

## 六、【侦探办案笔记】

### 本关指标口径总结

- 复购率三要素：**队列（X 月首购用户）+ 锚点（首购时间）+ 窗口（N 天内）**。
- 月内多单率 ≠ 复购率：前者看当月频次结构，后者看跨周期留存力；高频品类两者能差一倍。
- 复购订单必须晚于首购时间；当期首购当期再买，不算复购。
- 生鲜/日百报"30 天或 90 天复购率"；综合电商按品类分层；教育报"续报率"。

### 业务方对齐口径的标准提问话术

1. "这个复购率的**队列是哪个月的首购用户**？窗口是 **30 天、90 天还是 180 天**？"
2. "**当月首购当月再买**的用户，算不算在这版报表里？"
3. "和行业基准比的时候，**队列和窗口一致吗**？"

### 同类异常排查的通用方法论

"指标远超行业常识"类案件三步走：

1. **先找指标的真名**：65% 大概率不是复购率而是别的什么率——把 SQL 的分子分母翻译成人话；
2. **按队列拆结构**：把分子里的用户按首购月份分组，看哪些人根本不具备"复购"资格；
3. **用标准句式重算**："X 月首购用户的 N 天复购率"，跑出来的数如果落回行业常识带，结案。
