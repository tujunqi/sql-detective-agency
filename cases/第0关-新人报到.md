## 二、【指标卷宗】DAU 口径词典

**DAU（Daily Active Users，日活跃用户数）**：统计周期内（通常为一个自然日），与产品发生「有效互动」的去重用户数。听起来简单，但「有效互动」四个字，每个公司定义都不一样。

### 常见口径 A：登录口径（最宽）

- **计算逻辑**：当日产生登录行为（含 token 自动续期登录）的去重用户数。
- **适用场景**：强账号体系产品（社交、教育），登录埋点最稳定。
- **歧义坑点**：用户手机里 App 被系统唤醒、后台静默拉起也会触发登录埋点，这种「没睁眼的 DAU」算不算数？很多公司把它算进去了，DAU 因此虚高。

### 常见口径 B：行为口径（最常用）

- **计算逻辑**：当日产生任一「主动行为」（启动 App、浏览内容、搜索、点击）的去重用户数；纯后台拉起不算。
- **适用场景**：绝大多数互联网公司对外汇报用的就是它。
- **歧义坑点**：「启动」的埋点叫法五花八门（app_launch / first_open / app_start），漏埋一个，DAU 就塌一块；未登录游客算不算，不同团队答案经常相反。

### 常见口径 C：核心行为口径（最严）

- **计算逻辑**：当日完成核心价值行为的用户才算活跃——电商是「浏览商品/下单」，在线教育是「听课/交作业」，内容平台是「消费内容达 N 分钟」。
- **适用场景**：看「真实有效活跃」的内部经营分析，投资尽调也爱问这个口径。
- **歧义坑点**：核心行为的埋点往往不完善，用这个口径算出的 DAU 通常最小，和登录口径能差出一截。

### 行业差异速记

| 行业 | 通常口径 | 特殊之处 |
|---|---|---|
| 电商 | 行为口径（浏览即活跃） | 大促日 DAU 剧烈波动，要区分「自然活跃」与「促销拉动」 |
| 在线教育 | 核心行为口径（学习行为才算） | 假期与开学季波动大，试听用户常被单独统计 |
| 内容平台 | 行为口径 + 时长辅助 | 游客（免登录）占比高，必须先定「游客算不算用户」 |

### 面试标准回答话术

> "DAU 是统计周期内与产品发生有效互动的去重用户数。回答时我会先说清三件事：**一是活跃的定义**（登录、行为还是核心行为口径），**二是去重的键**（user_id、device_id 还是一人多号的 union id），**三是归天规则**（按什么时区、跨天行为归属哪一天）。口径不钉死，DAU 这个数没有意义。"

### 新手最容易踩的错误统计方式

1. **用 `COUNT(*)` 代替 `COUNT(DISTINCT user_id)`**——把「人次」当「人数」，用户一天登录 5 次就被算了 5 个 DAU。
2. **把多天的 DAU 直接相加**当成「多日活跃用户总数」——同一用户跨天重复出现，相加会虚高。
3. **忘记处理 NULL**——游客的 user_id 是空值时，`COUNT(DISTINCT user_id)` 会直接忽略他们（`COUNT(DISTINCT ...)` 不数 NULL）。

## 四、【探案任务】

### 第 1 步 · 口径对齐

陈探长的题目里其实藏着两个不同的指标。先回答：**「每天有多少个用户登录」和「每天一共发生了多少次登录」，分别应该用什么口径统计？**

<details>
<summary>点击查看提示（做完再看）</summary>

- 前者是 DAU：**人数口径**，按天去重用户，`COUNT(DISTINCT user_id)`。
- 后者是登录人次：**次数口径**，不去重，`COUNT(*)`。
- 关键动作是**先把日期归天**：`DATE(login_time)` 把时间戳切成自然日。

</details>

### 第 2 步 · 基础核算

写出 SQL：按天统计登录次数与 DAU，要求输出三列——日期、登录次数、DAU，并按日期排序。

<details>
<summary>点击查看提示</summary>

`GROUP BY DATE(login_time)` 一次分组，组内同时算 `COUNT(*)` 和 `COUNT(DISTINCT user_id)` 两个聚合值，一条 SQL 就够。

</details>

### 第 3 步 · 真相追踪

老板问："这三天**一共有多少个用户来过**？"——注意，不是"3+4+5=12"。写出 SQL 验证你的答案。

<details>
<summary>点击查看提示</summary>

多天合并统计时，去重范围要覆盖**整个三天**而不是单天：`COUNT(DISTINCT user_id)` 不带日期分组，才是跨天去重。

</details>

## 五、【真相大白】

### 5.1 分步解析

**第 1 步解析**：报案人问的两个数，本质是「去重人数」与「行为次数」的口径之争。DAU 永远指前者。SQL 里的对应关系：人数用 `COUNT(DISTINCT user_id)`，次数用 `COUNT(*)`。

**第 2 步解析**：`GROUP BY DATE(login_time)` 按自然日分组。`DATE()` 函数从 `DATETIME` 中抽出 `YYYY-MM-DD` 部分，同一用户同一天的多次登录会落进同一个组，方便组内去重。

**第 3 步解析**：跨天去重时不按日期分组，`COUNT(DISTINCT user_id)` 的作用域是整个结果集。同一用户三天都来，也只算 1 个人。

### 5.2 参考答案 SQL（逐行注释）

```sql
USE case00_newbie;

-- 【答案1 + 答案2】按天统计登录次数与 DAU
SELECT
  DATE(login_time)              AS login_date,   -- 归天：从时间戳中取出自然日
  COUNT(*)                      AS login_times,  -- 次数口径：登录了多少人次（不去重）
  COUNT(DISTINCT user_id)       AS dau           -- 人数口径：去重后的日活跃用户数
FROM user_login_log
GROUP BY DATE(login_time)                        -- 按自然日分组
ORDER BY login_date;                             -- 按日期升序，方便阅读

-- 【答案3】三天合计：跨天去重的活跃用户总数
SELECT
  COUNT(DISTINCT user_id) AS total_active_users  -- 不按日期分组，去重范围覆盖全部数据
FROM user_login_log;
```

**运行结果对照**（跑完后你可以逐项核对）：

| 日期 | 登录次数 | DAU |
|---|---|---|
| 2026-10-01 | 4 | 3 |
| 2026-10-02 | 4 | 4 |
| 2026-10-03 | 5 | 5 |

三天跨天去重活跃用户数 = **7**（u1、u2、u3、u4、u5、u6、u7），而不是 3+4+5=12。

### 5.3 错误写法对比

**错误写法一：用 `COUNT(*)` 当 DAU**

```sql
SELECT DATE(login_time) AS login_date, COUNT(*) AS dau  -- 错：这是人次
FROM user_login_log
GROUP BY DATE(login_time)
ORDER BY login_date;
```

错在哪：`COUNT(*)` 数的是行数。10 月 1 日 u1 登录了 2 次，被算成 2 个活跃用户。结果 10 月 1 日会得出 DAU=4，而真实值是 3，**虚高 1 人（偏差 +33%）**。这份数据量小偏差看起来不起眼，真实业务里人均一天启动五六次，偏差能放大 5 倍以上。

**错误写法二：把每天的 DAU 加总当成"三天总活跃"**

```sql
-- 错：3 + 4 + 5 = 12，把跨天重复的用户重复计数了
SELECT SUM(dau) FROM (
  SELECT COUNT(DISTINCT user_id) AS dau
  FROM user_login_log
  GROUP BY DATE(login_time)
) t;
```

错在哪：u1 三天每天都来，是同一个人，但相加时被算了 3 次。正确答案是 7，错误答案是 12，**虚高 71%**。需要跨天人数时，必须把去重范围拉大到整个时间窗。

## 六、【侦探办案笔记】

### 本关指标口径总结

- DAU = 当日有效互动的**去重用户数**，是人数，不是人次。
- 同一条 SQL 里 `COUNT(*)` 与 `COUNT(DISTINCT user_id)` 并排出现时，先想清楚每列的口径再命名——列名写错口径，读报表的人会拿着错的数做决策。
- 跨天统计，去重范围跟着时间窗走。

### 业务方对齐口径的标准提问话术

下次任何人报给你一个 DAU，先问这三句：

1. "这个 DAU 的**活跃定义**是什么？登录、启动还是核心行为？"
2. "**游客和未登录用户**算不算？去重用的 user_id 还是设备号？"
3. "数据**归天按哪个时区**？统计截止到几点（数据有没有跑完）？"

### 同类异常排查的通用方法论

数「人」的指标出现异常时，按顺序排查：

1. **口径核对**：分子分母、去重键、归天规则，和上一次报表是否一致；
2. **重复数据**：同一用户同一天是否被多次计数；
3. **空值与缺失**：NULL 是否被悄悄忽略或错误计入；
4. **上报完整性**：埋点是否丢了某端、某版本、某时段的数据。
