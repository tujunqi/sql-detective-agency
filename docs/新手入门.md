## 一、这是个什么游戏

你是一名新人数字侦探。每关是一起**业务数据异常案件**：DAU 暴跌、留存缩水、转化率虚高……报案人抱着报表找上门，你要用 SQL 查出真相。

但破案只是表象——**每个案子的真相背后，藏着一个高频业务指标的多种口径与歧义点**。破完 12 案，你对 DAU、留存、复购、ARPU、付费率、CTR、停留时长的理解，会超过大多数只刷过干净题库的候选人。

### 游戏规则

1. **读卷宗**：每关按「前情提要 → 案情通报 → 指标卷宗」的顺序读，卷宗里的口径词典是破案钥匙；
2. **还原现场**：把「案发现场」的 SQL 整段粘进 DataGrip 运行，数据就有了；
3. **限时解码**：探案任务第 2 步建议计时 5 分钟，自己先写出 SQL，再看「真相大白」；
4. **对照结案**：参考答案逐行注释，重点看**错误写法对比**——知道怎么错，比知道怎么对更值钱；
5. **领取徽章**：每关结案解锁一枚徽章，集齐 12 枚晋升首席侦探（见 [成就徽章系统](./成就徽章系统.md)）。

### 两种玩法

| 玩法 | 适合谁 | 入口 |
|---|---|---|
| 🎮 **游戏客户端** | 想先玩起来：侦探在大厅走格子，进案件室完成 4 个取证解谜（异常扫描 / 口径配对 / SQL 拼图 / 数字保险柜），集齐证据开锁结案；限时评级、徽章动画、进度自动保存 | 浏览器打开 `play/index.html`（本地双击或 GitHub Pages），手机也能玩 |
| 📄 **Markdown 卷宗 + DataGrip** | 想真刀真枪写 SQL：完整表结构、可复现数据、逐行注释答案 | 按本指南搭好环境，从 [第0关](../cases/第0关-新人报到.md) 开始 |

两种玩法共用同一套案件数据，建议**客户端过剧情、DataGrip 练真功**。

### 样例数据说明

各关数据为**脱敏小样本**（40~80 行），量级缩小但规律与真实业务一致——小到能心算复核，大到能跑出所有口径差异。真实业务里把数字乘以一万，坑还是那些坑。

## 二、SQL 环境搭建

本项目所有 SQL 严格遵循 **MySQL 8.0**。三选一：

### 方式 A：本地安装 MySQL（推荐，一次装好）

1. 下载：[MySQL Community Server 8.0](https://dev.mysql.com/downloads/installer/)（Windows 选 mysql-installer-community；macOS 选 DMG）；国内网络可用清华镜像；
2. 安装时记住你设置的 **root 密码**（教程模式默认端口 3306）；
3. 验证：终端执行 `mysql --version`，或安装 MySQL Workbench 后能连上即成功。

### 方式 B：Docker（最干净，一条命令）

```bash
docker run -d --name mysql8-detective \
  -e MYSQL_ROOT_PASSWORD=detective \
  -e MYSQL_DATABASE=detective \
  -p 3306:3306 mysql:8.0
```

连接信息：`127.0.0.1:3306`，用户 `root`，密码 `detective`。

### 方式 C：在线环境（零安装，应急用）

任何支持 MySQL 8.0 的在线 SQL 练习站（搜索 "online MySQL 8 sandbox"）都可运行本项目 SQL。注意：部分在线环境限制 `CREATE DATABASE`，可把每关脚本开头的建库语句去掉、直接建表。

## 三、DataGrip 安装与连接

DataGrip 是 JetBrains 出品的数据库 IDE，本项目所有 SQL 都在它里面验证过。

1. **安装**：[DataGrip 官网下载](https://www.jetbrains.com/zh-cn/datagrip/)，30 天试用后可用学生/开源许可；预算有限可平替：
   - **DBeaver Community**（免费开源，功能齐全）；
   - **VS Code + Database Client 插件**（轻量）；
   - **MySQL Workbench**（官方免费）；
2. **新建连接**：DataGrip → `+` → Data Source → MySQL：
   - Host：`127.0.0.1`，Port：`3306`，User：`root`，Password：你的密码；
   - 首次连接提示下载驱动，点 **Download** 等它装完；
   - URL 追加参数 `?useSSL=false&serverTimezone=Asia/Shanghai` 可避免时区告警；
3. **连接测试**：点 **Test Connection**，看到绿色对勾即可。

### 在 DataGrip 里复现一关（第 0 关为例）

1. 打开 [cases/第0关-新人报到.md](../cases/第0关-新人报到.md)，复制「案发现场」整段 SQL；
2. DataGrip 中打开一个 Query Console（`Ctrl+Shift+Q` / `Cmd+Shift+Q`），粘贴；
3. **全选**（`Ctrl+A`）→ 执行（`Ctrl+Enter`，macOS `Cmd+Return`）；
4. 左侧数据库列表刷新，看到 `case00_newbie` 库和 `user_login_log` 表即成功；
5. 下方结果区核对运行结果与文中「运行结果对照」是否一致；
6. 之后每一关同理：每关一个独立数据库（`case01_dau`、`case02_active_days`……），互不干扰。

> 💡 脚本开头都有 `DROP DATABASE IF EXISTS ...`，**重复运行会重置数据**，随时可以从头再办一遍案。

## 四、办案流程（每关通用）

```
读案情通报 → 研读指标卷宗（口径词典）
      ↓
运行案发现场 SQL（数据就位）
      ↓
第1步 口径对齐（先选题：分母是谁、去重键是什么）
      ↓
第2步 基础核算（⏱️ 限时 5 分钟，自己写 SQL）
      ↓
第3步 真相追踪（定位根因）
      ↓
对照真相大白（逐行注释 + 错误写法对比）
      ↓
侦探办案笔记 → 领徽章 → 下一关
```

三个办案习惯，从第 0 关就养成：

1. **先钉口径，再写 SQL**：分母是谁、去重键是什么、窗口关没关——没钉死口径的 SQL 是废案；
2. **错误写法也跑一遍**：每关的"错误写法对比"建议真的执行，亲眼看着数字怎么错，比背结论有效十倍；
3. **结案后过一遍自查清单**：[tools/口径自查清单.md](../tools/口径自查清单.md) 的 15 问，面试前过一遍等于复习全书。

## 五、常见报错 FAQ

**Q1：`Access denied for user 'root'@'localhost'`**
密码不对。本地安装时设置的密码；Docker 方式是 `detective`。忘记密码可重装或用 Docker 重建容器。

**Q2：`Unknown database 'case01_dau'`**
没有先运行该关的建库脚本。每个关卡的「案发现场」SQL 必须从第一行开始整段执行。

**Q3：中文注释 / 中文数据乱码**
确认三处都是 utf8mb4：建库语句里的 `DEFAULT CHARACTER SET utf8mb4`、DataGrip 连接 URL 的 `characterEncoding=utf8`（驱动会自动映射）、终端客户端的 `--default-character-set=utf8mb4`。

**Q4：`WITH RECURSIVE` 报语法错误**
MySQL 版本低于 8.0。递归 CTE、窗口函数都是 8.0 特性，`SELECT VERSION();` 检查版本，低于 8.0 请升级。

**Q5：DataGrip 执行只跑了选中的一段 / 跑了别的语句**
执行的是**光标所在语句**或**选中区域**。要跑整段脚本，先 `Ctrl+A` 全选再 `Ctrl+Enter`。

**Q6：存储过程模板报 `DELIMITER` 错误**
`DELIMITER` 是客户端指令，DataGrip 和 mysql 命令行都支持；个别在线沙箱不支持，跳过存储过程模板即可（不影响主线关卡）。

**Q7：想改数据做实验**
直接改。反正每关脚本重复运行即重置。建议实验方向：把第 1 关的 iOS 埋点"修好"再跑答案 SQL，观察 DAU 曲线变化——修数据是最好的理解方式。
